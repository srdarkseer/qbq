# QbQ benchmark summary

Generated by `benchmarks/summarize.py` from `benchmarks/results/*.json`. Do not edit by hand.
QbQ 0.1.0; every verification replays a trace 3x on a freshly seeded app and counts it only if it reproduces every time.

Each Bug Gym app has 4 independently togglable planted defects and 6 builds (patched, one per bug, all bugs), so there are 8 (build, bug) pairs to find per app. Recall@1 counts a bug as found only if the *first* planned test for its invariant is confirmed. FPR is computed over every planned test whose invariant no active bug breaks.

Across all apps: **24/24** findings get a patch that passes the gate. The gate requires the exploit to reproduce on 0 of 3 runs and every previously passing functional QA test to still pass. A regression test is *valid* when the exported standalone pytest file fails on the unpatched build and passes on the patched code.
